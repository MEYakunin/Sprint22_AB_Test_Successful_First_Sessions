# Sprint22. A/B-тестирование: доля успешных первых сессий

Учебный проект по разработке дизайна A/B-теста и анализу его результатов для
развлекательного приложения с «бесконечной» лентой коротких видео.

## Контекст задачи

Продукт удерживает внимание пользователя за счёт алгоритма рекомендаций. Ранее лента
формировалась эвристиками «популярное за день + новинки», теперь команда Data Science
разработала новый алгоритм ранжирования контента. Требуется проверить, повышает ли он
глубину просмотра и удержание, и вынести вердикт о внедрении для всех пользователей.

**Основная метрика:** доля успешных первых сессий — сессия считается успешной, если
пользователь просмотрел не менее 4 страниц (`page_counter >= 4`).

## Данные

Данные загружаются из публичного хранилища `https://code.s3.yandex.net/datasets/`:

| Файл | Содержимое | Использование |
|---|---|---|
| `sessions_project_history.csv` | 435 924 сессии, 134 039 пользователей, 11.08–23.09.2025 | EDA, расчёт базового значения метрики и параметров теста |
| `sessions_project_test_part.csv` | 3 130 сессий за первый день теста (14.10.2025) | мониторинг корректности сплитования |
| `sessions_project_test.csv` | 100 005 сессий за 14–20.10.2025 | проверка результатов эксперимента |

Ключевые колонки: `user_id`, `session_id`, `session_date`, `session_start_ts`,
`install_date`, `session_number`, `registration_flag`, `page_counter`, `region`,
`device`, `test_group`.

## Структура ноутбука

`Sprint22_AB_Test_Successful_First_Sessions_Yakunin_Mikl.ipynb`

1. **Работа с историческими данными (EDA)**
   - загрузка и проверка качества данных;
   - срез первых сессий, проверка «одна первая сессия на пользователя»;
   - динамика числа первых сессий и среднее дневное значение;
   - распределение глубины просмотра `page_counter`;
   - историческая доля успешных первых сессий и её динамика.
2. **Подготовка к тесту**
   - основная, прокси- и барьерные метрики;
   - относительный MDE 5% и его перевод в абсолютный (1.55 п.п.);
   - одностороннее направление проверки (`alternative='larger'`);
   - размер выборки через `proportion_effectsize` и `NormalIndPower`;
   - длительность теста.
3. **Мониторинг A/B-теста**
   - проверка распределения пользователей по группам;
   - проверка пересечений пользователей;
   - равномерность распределения по устройствам и регионам.
4. **Проверка результатов**
   - подготовка данных и ограничение периодом 14–20 октября;
   - формулировка нулевой и альтернативной гипотез;
   - сравнение доли успешных первых сессий в группах;
   - односторонний z-тест для долей.
5. **Выводы для продуктовой команды**

## Параметры эксперимента

| Параметр | Значение |
|---|---|
| Базовое значение метрики, `p1` | 31.0% |
| Относительный MDE | +5% |
| Абсолютный MDE | 1.55 п.п. |
| Ожидаемое значение, `p2` | 32.55% |
| Уровень значимости, `alpha` | 0.05 |
| Мощность, `power` | 0.80 (`beta = 0.2`) |
| Направление проверки | одностороннее, `larger` |
| Размер одной группы | 11 156 пользователей |
| Общий размер выборки | 22 312 пользователей |
| Расчётная длительность | 6 дней → принято 7 дней |

## Результаты

| Показатель | Значение |
|---|---|
| Фактические размеры групп | 15 108 (A) и 15 342 (B), всего 30 450 |
| Доля успешных первых сессий, группа A | 31.50% |
| Доля успешных первых сессий, группа B | 31.23% |
| Абсолютное изменение (B − A) | −0.27 п.п. |
| Относительное изменение | −0.84% (ожидалось +5%) |
| p-value одностороннего z-теста | 0.6911 |
| Статистический вывод | H₀ не отклоняется |

**Качество эксперимента:** расхождение размеров групп 0.74%, пересечений пользователей
между группами нет, распределение по устройствам и регионам однородно (максимальные
расхождения 1.7 п.п. и 0.4 п.п.).

**Итоговая рекомендация:** новый алгоритм **не рекомендуется к внедрению** — заявленный
рост основной метрики не подтверждён ни описательно, ни статистически. Алгоритм стоит
отправить на доработку и провести повторный тест, контролируя барьерные метрики.
